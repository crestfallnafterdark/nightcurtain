## Invariants

- Leaf: zero imports; all persistence goes through the injected `CredentialStoragePort`.
- `createBrowserCredentialStorage()` is the single declared ambient (`localStorage`) touchpoint; class instances never fall back to ambient storage.
- This module is the only application reader and writer of `CREDENTIAL_VAULT_STORAGE_KEY` (`'ai_story_credentials_v1'`); no application consumer touches credential storage directly (the sanctioned QA seeder `tests/qa/seed_vault.mjs` writes and verifies the key on the MCP profile — see `docs/testing/exploratory_qa_plan.md` §2).
- Secrets stay confined to full entries: `createResolverPort()` returns the `{ id, apiKey?, encryptionKey? }` projection only, `exportCredentials()` is redacted by default, and secrets never appear in errors or logs.
- Canonical-credential creation on lookup is the sole mutating read path through an otherwise read-only resolver (ratified exception); the resolver exposes no writes, enumeration, or listing.
- The API is synchronous and emits no events or subscriptions.
- Corrupt persisted JSON silently falls back to an empty state; storage/quota failures propagate unguarded to the caller.

## Decisions

- `CredentialResolverPort` is the canonical registry-listed port provided by this module, constructed as a frozen plain object via `vault.createResolverPort()` (ratified port contract)
- The vault is a pure `(keyId, secret)` store: `baseUrl` is dropped outright from entries and mutations, with no migration (pre-release)

## API docs

### `createBrowserCredentialStorage` — function

Creates the declared browser storage adapter (`{ get, set, remove }`).

Mirrors the source module's storage-resolution guard order: when `window` is undefined or `globalThis.localStorage` is undefined, a Map-backed in-memory port is returned (preserving Node-test behavior); otherwise `localStorage` backs the port directly.

#### Returns

A `CredentialStoragePort` over `localStorage` or an in-memory fallback.

### `CREDENTIAL_VAULT_STORAGE_KEY` — variable

Storage key under which the serialized `CredentialVaultData` JSON lives (`'ai_story_credentials_v1'`). Single storage path for application code: no application module reads or writes this key directly; the sanctioned QA seeder (`tests/qa/seed_vault.mjs`) is the sole outside writer and verifier (see `docs/testing/exploratory_qa_plan.md` §2).

### `CredentialEntry` — interface

A labeled credential record stored by the vault. Arbitrary passthrough fields survive round-trips (the vault spreads caller-provided entries).

#### Members

- **`index signature`** — Arbitrary passthrough fields preserved verbatim from callers. `baseUrl` is **not** preserved: the vault is a pure `(keyId, secret)` store per the v1.1.0 amendment (BUG-ENC-027) — all mutation paths (`addCredential`, `updateCredential`, `importCredentials`) drop it, and the custom endpoint URL lives in the model config (`AgentModelConfig.url`).
- **`apiKey`** — Secret API key (absent on redacted `exportCredentials()` results).
- **`createdAt`** — Epoch-ms creation timestamp (`0` for lazily created canonical entries).
- **`encryptionKey`** — Optional Prem AI client-side encryption key (absent on redacted exports).
- **`id`** — Unique credential id (`canonical_<providerId>` for canonical entries).
- **`isCanonical`** — True for lazily created canonical entries.
- **`label`** — Human-readable label used by management UIs.
- **`lastUsed`** — Legacy field, retained on entries but never written after creation.
- **`providerId`** — Normalized provider id (see `normalizeProviderId`).

### `CredentialProjection` — interface

Least-privilege credential projection returned by the resolver port. Only the credential id and the two secret fields inference consumes.

#### Members

- **`apiKey`** — API key, omitted when the underlying entry has none.
- **`encryptionKey`** — Prem AI client KEK, omitted when the underlying entry has none.
- **`id`** — Credential id.

### `CredentialResolverPort` — interface

Canonical read-only credential resolver port (registry-listed).

Constructed as a frozen plain object via `CredentialVault.createResolverPort()` and handed to runtime/domain consumers (e.g. MOD-15 `createProvider`). Returns least-privilege projections rather than full vault entries — no writes, no enumeration, no listing.

**Ratified exception (MOD-16):** a lookup miss for a canonical provider id may lazily create and persist that canonical credential; this is the sole mutating read path, documented in the module invariants.

#### Members

- **`getActiveCredential`** — Active credential for a provider id (e.g. `'runware'`, `'deepseek'`).
- **`getCredential`** — Lookup by credential id (as referenced by `AgentModelConfig.keyId`).

### `CredentialStoragePort` — interface

Injected storage port (non-canonical internal DI, not registry-listed).

The composition root provides the implementation and the vault is the sole consumer. `createBrowserCredentialStorage()` is the single declared ambient (`localStorage`) touchpoint; class instances never fall back to ambient storage on their own.

#### Examples

```typescript
const backing = new Map<string, string>();
const storage: CredentialStoragePort = {
  get: key => (backing.has(key) ? backing.get(key)! : null),
  set: (key, value) => void backing.set(key, value),
  remove: key => void backing.delete(key)
};
const vault = new CredentialVault({ storage });
```

#### Members

- **`get`** — Reads the raw JSON string for `key`, or `null` when absent.
- **`remove`** — Removes the value stored under `key`.
- **`set`** — Persists `value` under `key` (storage/quota errors propagate to the caller).

### `CredentialVault` — class

Labeled credential vault with injected persistence.

All mutation flows through the injected `CredentialStoragePort`; the API is synchronous, emits no events, and never logs. Storage/quota errors propagate unguarded (source-verbatim). Internals are `#`-private and deliberately absent from this contract; this declaration covers the public surface only.

#### Examples

```typescript
import { CredentialVault, createBrowserCredentialStorage } from './credentialVault/index.ts';

const vault = new CredentialVault({ storage: createBrowserCredentialStorage() });
const entry = vault.addCredential({ providerId: 'runware', label: 'Main', apiKey: 'sk-...' });
vault.setActiveCredential('runware', entry.id);

const resolver = vault.createResolverPort();
resolver.getActiveCredential('runware')?.apiKey;
```

#### Members

- **`constructor`** — Creates a vault over the supplied storage port.
- **`addCredential`** — Adds a credential entry, assigning `id`, `createdAt`, and `lastUsed: null`. Arbitrary extra fields are preserved by spread, except `baseUrl`, which is dropped (BUG-ENC-027 — the vault stores `(keyId, secret)` pairs only).
- **`createResolverPort`** — Builds the canonical read-only `CredentialResolverPort`: a frozen plain object returning least-privilege `{ id, apiKey?, encryptionKey? }` projections. No writes, no enumeration.
- **`deleteCredential`** — Deletes a credential by id. Canonical entries are wiped in place (secrets cleared, entry retained); non-canonical entries are removed and the active pointer is re-pointed or cleared.
- **`exportCredentials`** — Exports credentials redacted by default (`apiKey`/`encryptionKey` removed). This is the redacted-by-default export surface; `includeSecrets: true` is the explicit opt-in escape hatch.
- **`getActiveCredential`** — Returns the active credential for a provider. Falls back to the first stored credential, then lazily creates and persists the canonical entry.
- **`getAllCredentials`** — Returns every stored credential, including secrets.
- **`getCredential`** — Looks up a credential by id. **Mutating read:** a missing `canonical_*` id lazily creates, persists, and returns the canonical entry (ratified exception).
- **`getCredentialsForProvider`** — Returns all credentials for a provider, lazily creating and persisting the canonical entry when none exist.
- **`importCredentials`** — Imports credentials, overwriting entries by id and assigning missing ids by mutating the caller's objects. `baseUrl` is dropped from imported entries, as in `addCredential`/`updateCredential` (BUG-ENC-027 — the vault stores `(keyId, secret)` pairs only).
- **`maskKey`** — Masks a secret for display: keeps `visibleStart` leading and `visibleEnd` trailing characters, collapsing keys whose length is at most `visibleStart + visibleEnd` (the boundary includes equality) to `'****'`. Falsy/non-string input yields `''`.
- **`setActiveCredential`** — Sets the active credential for a provider; a falsy `credentialId` clears the pointer, after which the normal active-resolution path re-selects or lazily creates the canonical entry.
- **`updateCredential`** — Updates a credential by id. A missing `canonical_*` id lazily creates that canonical entry with the updates applied and marks it active. `baseUrl` is dropped from the updates (BUG-ENC-027).
