## Invariants

- The module-level `enclaveClientCache` (keyed by credential id or `apiKey:clientKEK`, value = creation promise) and `defaultModuleKEK` singletons are preserved: they stay module-scope and are reachable only through `getPremEnclaveClient`, `getDefaultClientKEK`, and `resetPremEnclaveClient`.
- A failed enclave-client creation evicts its cache entry, so a later call may retry.
- Concurrent callers for the same cache key share the exact same creation promise — and therefore the same client identity.
- `createPremEnclaveClient` honors only a valid 64-hex `clientKEK` verbatim; any other value yields a freshly generated KEK, while the provider constructor's missing-KEK path uses the memoized module default.
- The gateway URL is trimmed of trailing slashes and defaults to `https://gateway.prem.io`; attestation is disabled and request/OpenAI timeouts are fixed at 300 000 ms.
- Providers are treated as immutable after construction (members are `readonly` in this contract, but instances are not runtime-frozen) except the documented lazy enclave-client memoization on `getClient()`; `PremModel.config` is frozen at construction.
- `PremModel` honors `config.transformPayload` as the sole payload mutation hook (it receives the assembled enclave request body and its return value is sent); of the `ModelConfig` keys, only `temperature` is forwarded (`maxTokens`, `reasoningEffort`, `routing`, `serviceTier` are accepted but ignored) and `max_tokens` is fixed at 100 000.
- Non-OK HTTP responses from `listModels` throw `InferenceError` with `status`, code `ERR_HTTP_<status>`, endpoint `details`, and `retryable` from the shared retry classifier; it extends `Error`, so `catch (Error)` consumers stay compatible.
- `PremModel` construction and `PremProvider.createModel` throw `TypeError` on a falsy model id; transport performs no model-id fallback (MC-4).
- `checkBalance()` is unsupported for the enclave: it performs no network call, never throws, and always resolves to `{ available: false, balance: null }`.
- `getEffectiveClientKEK()` precedence: a valid 64-hex `encryptionKey` on the credential referenced by `credentialId` wins over the construction KEK when `vault` is injected and the lookup yields one, falling back to `''`.

## API docs

### `createPremEnclaveClient` — function

Creates a Prem confidential-enclave client.

A valid 64-hex `clientKEK` is used verbatim; any other value falls back to a fresh `generateNewClientKEK()`. The gateway URL is trimmed of trailing slashes and defaults to `https://gateway.prem.io`. Attestation is disabled and request/OpenAI timeouts are fixed at 300 000 ms.

#### Parameters

- `options` — Enclave construction parameters.

#### Returns

The resolved RvencClient (SDK-typed as `any`).

#### Throws

- Any rejection raised by the underlying SDK client construction.

### `getDefaultClientKEK` — function

Returns the module-level default client KEK, generating and memoizing one on first use. The identity is stable until `resetPremEnclaveClient()` is called without a cache key.

#### Returns

64-hex client KEK.

### `getPremEnclaveClient` — function

Returns the cached enclave client promise for `cacheKey`, or creates and caches one. A failed creation removes the cache entry so a later call may retry; concurrent callers reuse the exact same cached creation promise (and therefore the same client identity).

#### Parameters

- `cacheKey` — Cache identity (credential id, or `apiKey:clientKEK`).
- `options` — Enclave construction parameters, used only on cache miss.

#### Returns

Shared RvencClient promise.

### `PremModel` — class

Prem AI Confidential Enclave Model Implementation.

`id` must arrive fully resolved (MC-4 removed the transport-level fallback; MOD-15 invariant 4: no default model ids in transport); `config` is frozen after construction. `config.transformPayload` is honored as the sole payload mutation hook; of the `ModelConfig` keys, only `temperature` is forwarded. `tools` from request options are included when non-empty; `max_tokens` is fixed at 100 000 and a caller-supplied `config.maxTokens` is ignored.

### `PremProvider` — class

Prem AI Provider Client-Encrypted Security Enclave provider implementation.

Members are declared `readonly` and instances are treated as immutable after construction, but they are not runtime-frozen. The sole mutation is the documented lazy enclave-client memoization on the instance (`getClient()`), backed by the module-level singleton cache.

#### Members

- **`constructor`** — Constructs a Prem provider. `options` may be a legacy bare API-key string (KEK argument applied as-is, defaulting to the module KEK) or a PremProviderOptions bag. In the bag form, a malformed non-64-hex `clientKEK` is preserved verbatim (only a missing/empty value falls back to `getDefaultClientKEK()`), and the gateway URL is trimmed of trailing slashes.
- **`checkBalance`** — Balance lookup is unsupported for the enclave: never throws and always resolves to `{ available: false, balance: null }`.
- **`createModel`** — Creates a Prem model bound to this provider.
- **`credentialId`** — Credential id resolved through the injected resolver, when supplied.
- **`getClient`** — Lazily resolves the enclave client through the module-level cache: an injected `client` wins, otherwise `getPremEnclaveClient` is called with the credential id (or `apiKey:clientKEK`) as the cache key. The resolved client is memoized on the instance.
- **`getEffectiveApiKey`** — Resolves the effective API key: explicit `credentialId` + `vault` lookup first, then the directly supplied key, then the vault's active credential for the `prem` provider; empty string when nothing resolves.
- **`getEffectiveClientKEK`** — Resolves the effective client KEK: a 64-hex `encryptionKey` from the credential referenced by `credentialId` wins when `vault` is injected and the lookup yields one, otherwise the construction KEK (or empty string).
- **`getProviders`** — Prem has no provider-routing hub: always returns an empty array.
- **`id`** — Provider instance identifier (always `'prem'`).
- **`listModels`** — Discovers chat models from the configured gateway's `/rvenc/models` endpoint (default gateway `https://gateway.prem.io`).
- **`vault`** — Injected credential resolver used for dynamic API-key/KEK resolution; the `credentialId` lookup (API key and KEK override) requires an injected `vault` — without one, `credentialId` is ignored.

### `PremProviderOptions` — interface

Construction options for PremProvider.

`client` is an injected RvencClient reference used to bound enclave resource footprint; when present it short-circuits lazy creation in `getClient()`. `credentialId`/`vault` drive dynamic credential resolution and `apiKey` is the pre-resolved fallback. `gatewayUrl` overrides the vendor endpoint. `clientKEK` is consumed by two paths: the provider constructor preserves any non-empty value verbatim (only a missing/empty value falls back to the module default), while createPremEnclaveClient honors it only when it is a valid 64-hex string and otherwise generates a fresh KEK. Both `client` and `gatewayUrl` are preserved injection/test hooks: no in-repo production caller supplies them.

#### Members

- **`apiKey`** — Pre-resolved Prem API key.
- **`client`** — Injected RvencClient reference to bound enclave resource footprint. Preserved injection/test hook: no in-repo production caller supplies it; when present it short-circuits lazy creation in `getClient()`.
- **`clientKEK`** — Explicit client KEK; the provider preserves any non-empty value, while createPremEnclaveClient honors only a valid 64-hex value.
- **`credentialId`** — Credential id resolved through the injected resolver.
- **`gatewayUrl`** — Gateway base URL override (default `https://gateway.prem.io`). Preserved injection/test hook: no in-repo production caller supplies it.
- **`vault`** — Injected credential resolver used for dynamic API-key/KEK resolution; the `credentialId` lookup (API key and KEK override) requires an injected `vault` — without one, `credentialId` is ignored.

### `resetPremEnclaveClient` — function

Resets module-level enclave client state.

With a `cacheKey`, only that cache entry is evicted (the default KEK is left untouched). Without one, the whole cache is cleared AND the default module KEK is reset, so the next `getDefaultClientKEK()` generates a fresh value. Preserved reset/test helper: no in-repo production caller invokes it; it is exported for test isolation and legacy parity.

#### Parameters

- `cacheKey` — Specific cache entry to evict; omit to clear all.
